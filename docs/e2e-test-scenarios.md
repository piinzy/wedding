# سيناريوهات الاختبار الشامل — منصة رباط
> يُعاد تشغيل هذا الاختبار مع كل تغيير جوهري في النظام قبل الدمج على main

---

## المتطلبات الأساسية
- حساب Supabase مشغّل مع migration 001 و 002 مطبّقَين
- متصفح + وضع Incognito (لضمان عدم وجود جلسة سابقة)
- بريد إلكتروني تجريبي حقيقي (يستقبل رسائل التفعيل)

---

## السيناريو 1: تسجيل منظّم فعالية جديد

| # | الخطوة | النتيجة المتوقعة | الحالة |
|---|--------|-----------------|--------|
| 1.1 | افتح `/register` | تظهر شاشة اختيار نوع الحساب (منظّم / مورد) | ☐ |
| 1.2 | اختر **منظّم فعالية** | تنتقل للخطوة 2: اختيار نوع المناسبة | ☐ |
| 1.3 | اختر **زفاف** (أو أي نوع) | تنتقل للخطوة 3: المعلومات الشخصية | ☐ |
| 1.4 | أدخل بيانات صحيحة (اسم، بريد، كلمة مرور +8 أحرف) | تقبل النموذج وتظهر شاشة "تحقق من بريدك" | ☐ |
| 1.5 | افتح البريد الوارد واضغط رابط التفعيل | يُعاد توجيهك لـ `/dashboard` | ☐ |
| 1.6 | تحقق من قاعدة البيانات: `auth.users` + `public.users` + `event_organizer_profiles` | يوجد صف في كل جدول بالبيانات الصحيحة | ☐ |

**حالات الحافة:**
- [ ] تسجيل ببريد مستخدم سابقاً → رسالة خطأ واضحة بالعربي
- [ ] كلمة مرور أقل من 8 أحرف → رسالة خطأ قبل الإرسال
- [ ] ترك حقل إلزامي فارغاً → لا يُرسل النموذج

## السيناريو 2: تسجيل مورد خدمات جديد

| # | الخطوة | النتيجة المتوقعة | الحالة |
|---|--------|-----------------|--------|
| 2.1 | افتح `/register` في Incognito | تظهر شاشة اختيار نوع الحساب | ☐ |
| 2.2 | اختر **مورد خدمات** | تنتقل مباشرة للخطوة 3 (بدون اختيار نوع مناسبة) | ☐ |
| 2.3 | أدخل بيانات صحيحة | شاشة "تحقق من بريدك" | ☐ |
| 2.4 | فعّل الحساب من البريد | يُعاد توجيهك لـ `/vendor` | ☐ |
| 2.5 | تحقق من قاعدة البيانات: `public.users` بـ role=vendor | صف واحد بالدور الصحيح | ☐ |

## السيناريو 3: تسجيل الدخول وتوجيه الأدوار

| # | الخطوة | النتيجة المتوقعة | الحالة |
|---|--------|-----------------|--------|
| 3.1 | افتح `/login` في Incognito | تظهر صفحة الدخول | ☐ |
| 3.2 | سجّل دخول كـ **منظّم** | يُعاد التوجيه لـ `/dashboard` | ☐ |
| 3.3 | سجّل دخول كـ **مورد** | يُعاد التوجيه لـ `/vendor` | ☐ |
| 3.4 | سجّل دخول كـ **أدمن** | يُعاد التوجيه لـ `/admin` | ☐ |
| 3.5 | حاول الوصول لـ `/admin` بحساب منظّم | يُعاد التوجيه لـ `/dashboard` | ☐ |
| 3.6 | حاول الوصول لـ `/dashboard` بدون تسجيل دخول | يُعاد التوجيه لـ `/login` | ☐ |

**حالات الحافة:**
- [ ] كلمة مرور خاطئة → رسالة خطأ "بيانات دخول غير صحيحة"
- [ ] حساب غير مفعّل → رسالة "تحقق من بريدك الإلكتروني"
- [ ] الضغط على "نسيت كلمة المرور" → الوصول لـ `/forgot-password`

## السيناريو 4: تسجيل الخروج
